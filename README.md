# 水果連連看 🍓🔗🍍

可愛風連連看。兩個一樣的水果，只要中間存在一條**只走上下左右、只經過空格、轉彎不超過 2 次**的路徑，
就能一起消掉；路徑可以繞到盤面外面那一圈，所以最外圈的水果不會被困住。

- **單機闖關**：幼幼班 →第一關 → 第二關 → 第三關，分數累加。
- **幼幼班 👶**：專門給 **3～5 歲**小朋友 —— 4 × 3 十二格、只有三種水果、格子很大、
  時間長到幾乎沒有壓力、提示與洗牌不限次數，而且每一顆水果都會寫上名字。
- **線上競速**：最多 **6 個人共用同一張盤面**，同一對水果**誰先連到就是誰的分**，
  另有觀戰、邀請連結、聊天室與即時戰況。
- 手機／平板／桌機、直向橫向都能玩；右上角有設定。

## 最快開始（在自己電腦上玩）

雙擊 **`啟動遊戲.bat`**（第一次會自動 `npm install`），瀏覽器會自己打開
<http://localhost:3040>。

視窗裡會印出「同網段」網址，例如 `http://192.168.1.23:3040` ——
同一個 Wi-Fi 下的手機、平板、其他電腦輸入這個網址就會進到同一個大廳，可以直接開房競速。

指令版：

```bash
npm install
npm start           # http://localhost:3040
```

## 玩法

### 連線規則

| 折數 | 說明 |
|---|---|
| 0 折 | 同一列或同一行，中間一路都是空格 |
| 1 折 | 轉一次彎，轉角必須是空格 |
| 2 折 | 轉兩次彎，常常是繞到盤面外圈那一圈 |
| 3 折以上 | **不算**，連不起來 |

> 盤面內部四周固定多留一圈空白，連線可以繞出去 —— 這是連連看的標準規則，
> 少了它，最外圈的水果常常會變成無解。

### 計分

| 項目 | 分數 |
|---|---|
| 連成一對 | 基礎 **100** 分 |
| 連擊加成 | **5 秒**內接著連下一對，每次 **+10%**，最多 **×2.0** |
| 連錯 | **不扣分**，只把連擊歸零（對小朋友友善） |
| 過關剩餘時間 | 每剩 1 秒 **+2** 分（清空盤面才有） |

### 四個關卡

| 關卡 | 盤面 | 水果種類 | 時間 | 提示 | 洗牌 |
|---|---|---|---|---|---|
| 🍼 幼幼（3～5 歲） | 4 × 3 | 3 種 | 600 秒 | ∞ | ∞ |
| 🍓 簡單 | 8 × 6 | 6 種 | 240 秒 | 5 次 | 5 次 |
| 🍍 普通 | 10 × 8 | 10 種 | 300 秒 | 3 次 | 3 次 |
| 🥑 困難 | 12 × 10 | 14 種（開始混進蔬菜） | 360 秒 | 2 次 | 2 次 |

### 提示、洗牌與死局

- 💡 **提示**：點亮一組還能連的水果。
- 🔀 **洗牌**：把剩下的水果重新排一次，而且**保證重排後一定還有解**。
- 消除之後水果**位置固定不動**，所以偶爾會走到「誰都連不到」的死局 ——
  這時候系統會**自動免費洗牌**，不會浪費玩家的次數。

### 操作

- **觸控／滑鼠**：點一下選起來，再點第二個送出；點同一個取消；點到不同種水果會直接把選取換過去。
- **鍵盤**：方向鍵移動、Enter／空白鍵選取、Esc 取消。
- **螢幕閱讀器**：每一格都會唸出第幾列第幾行、哪一種水果、有沒有被選起來。

## 模式

### 單機闖關

從任何一關開始都可以，過關後可以直接接下一關，分數累加。
每一關的最高分、最快時間與最高連擊會存在這台裝置的瀏覽器裡（不會上傳）。

### 線上競速（最多 6 人）

全部人看**同一張盤面**，同一對水果先連到的人得分，慢一步只會撲空（不扣分）。
時間到或盤面被清空就結算，分數最高的人贏。

| | |
|---|---|
| 玩家席位 | 最多 6 人；席位滿了或對局進行中進來的人會**先變成觀戰**，下一局才能下場 |
| 觀戰 | 看得到盤面、即時排行與聊天室，但不能出手（權限旗標由伺服器算好才給前端） |
| 邀請連結 | 房主可產生「下場玩／只觀戰」兩種邀請，預設 30 分鐘、最多 5 人用，可隨時撤銷 |
| 提示 | **個人的**，只有自己看得到，不會幫對手指路 |
| 洗牌 | 會動到共用盤面，所以全房都會收到並同步 |
| 斷線 | 座位保留 60 秒，用同一台裝置重新整理就會回到原位 |
| 房號 | 5 碼，拿掉容易看錯的 0 O 1 I |

## 版面

- **桌機／平板橫向**：左邊一條窄側欄同時放「即時戰況」與「聊天室」，其餘全部留給盤面，
  盤面依可用空間**等比長到最大**。
- **手機／平板直向**：側欄收成從左邊滑出的抽屜（左下角有 📊 與 💬 兩個開關），
  盤面吃滿寬度，即時排行改成盤面上方／左側的浮條（不擋觸控）。
- 每個畫面**右上角**都有 ⚙ 設定：背景音樂與音效**分開**開關與音量、觸控震動、減少動態、
  顯示水果名稱。設定會記在本機，重新整理還在。

## 專案結構

```
fruit-link/
├─ public/
│  ├─ index.html
│  ├─ css/style.css
│  └─ js/
│     ├─ config.js     全站唯一的 server URL 設定入口（?server= / 建置注入 / 同源）
│     ├─ rng.js        可注入的種子亂數（同一個種子 = 同一張盤面）
│     ├─ rules.js      規則核心：連線判定、盤面生成、洗牌、計分（前後端共用）
│     ├─ fruits.js     水果造型（純資料，32 種）
│     ├─ storage.js    本機偏好與個人紀錄
│     ├─ svgui.js      立體 SVG 按鈕、水果磚、LOGO、獎盃
│     ├─ audio.js      Web Audio 即時合成的音樂與音效（不需要任何音檔）
│     ├─ render.js     盤面、連線動畫、特效、側欄清單
│     ├─ online.js     Socket.IO 連線包裝
│     └─ app.js        畫面流程與輸入
├─ lib/rooms.js        房間、座位、觀戰、邀請、聊天、對局生命週期（只在伺服器跑）
├─ server.js           Express + Socket.IO 權威伺服器
├─ tests/verify.js     規則與房間的單元測試
├─ scripts/
│  ├─ online-check.js  真的開伺服器跑一輪線上流程
│  ├─ browser-check.js 真的開瀏覽器跑 RWD 與單機一局
│  └─ inject-server-url.js
└─ 啟動遊戲.bat
```

**規則只有一份。** `public/js/rules.js` 同時被瀏覽器（單機）、`server.js`（線上）
與測試 `require`，所以單機和線上不可能長出兩套會漂移的判定。
線上模式前端只送「我點了哪兩格」，能不能連、加幾分、那兩格還在不在，全部由伺服器說了算。

## 驗證

```bash
npm test              # 規則與房間單元測試（49 項）
npm run test:online   # 真的開伺服器、接真的 Socket.IO 用戶端跑一輪（38 項）
npm run verify        # 上面兩個一起跑

npm run test:browser  # 真的開瀏覽器：RWD 八種尺寸 + 單機一局 + 設定流程（96 項）
```

`test:browser` 需要 Playwright 的瀏覽器：

```bash
npx playwright install chromium
# 不能下載的環境，可以指到系統既有的 Chromium：
PW_CHROMIUM=/path/to/chrome npm run test:browser
```

## 部署

### 伺服器（Render 免費方案）

在 Render 選 **New → Blueprint**、指到這個 repo，`render.yaml` 已經寫好了。
記得設 `GAME_ALLOWED_ORIGIN`（前端另外放的話填前端網址；同一個服務可以留 `*`）。

免費方案的限制已經設計進去了：

- 閒置約 15 分鐘會**休眠**，第一次連線要等十幾秒喚醒 —— 前端 `/health` 的逾時放寬到 10 秒。
- 檔案系統是**暫時的** —— 房間只存在記憶體，不寫任何檔案，服務重啟後房間消失是預期行為。
- 有 CPU／頻寬配額 —— 搶消是**事件驅動**（不是每幀送完整盤面），
  主迴圈只負責「時間到就結算」，空房與打完很久的房間會自動回收。

### 前端（GitHub Pages）

推上 `main` 就會自動跑 `.github/workflows/deploy-pages.yml`：
把 repository variable **`GAME_SERVER_URL`** 注入 `public/js/config.js` 之後發佈 `public/`。

> 設定位置：Settings → Secrets and variables → Actions → Variables → `GAME_SERVER_URL`
> 例如 `https://fruit-link.onrender.com`

**server URL 只有 `public/js/config.js` 這一個入口**，其他檔案不准寫死網址。
解析順序：`?server=` 網址參數 → 建置注入 → 同源 → 都沒有就只能玩單機。
`https` 頁面不接受 `http` 伺服器（瀏覽器會擋混合內容），格式不合會被擋下並停用線上功能，
**不會**靜默回退到 localhost 或任何寫死的網域。

跨電腦臨時測試可以直接用網址參數：

```
https://你的帳號.github.io/fruit-link/?server=https://fruit-link.onrender.com
```

### 環境變數

| 變數 | 預設 | 說明 |
|---|---|---|
| `PORT` | 3040 | 監聽埠（Render 會自動注入） |
| `HOST` | 0.0.0.0 | 監聽介面 |
| `GAME_ALLOWED_ORIGIN` | `*` | 允許連進來的前端來源，逗號分隔 |
| `COUNTDOWN_MS` | 3000 | 開賽倒數 |
| `GAME_SERVER_URL` | — | **前端**建置時要注入的伺服器位址 |

完整範例見 `.env.example`。秘密與本機設定都不進版控。

## 素材與授權

- 水果造型是這一套小遊戲共用的手繪 SVG（沿用 `flip-match` 的蔬果牌組），沒有外部素材。
- 音樂與音效是 Web Audio **即時合成**的，不需要任何音檔，也沒有授權問題。
- 想換成正式美術或音樂的話：造型改 `public/js/fruits.js`，聲音改 `public/js/audio.js` 的 `SFX` 與 `MEL`。
